# ML-сервис трамвайного прогноза

## Что работает

FastAPI обслуживает существующий HTTP-контракт `docs/ml-contract.md`.
Backend отправляет `POST /predict` с `{"horizon":"day","date":"2025-11-01"}`,
получает JSON для сети и сохраняет его в своей PostgreSQL. Веса и профили загружаются
один раз при старте. Переобучения, чтения 60 млн транзакций и внешних HTTP-запросов
при прогнозировании нет. ONNX не используется.

Основа — ранее выбранная Ridge-регрессия дневного логарифма валидаций, поправка
по недавней истории и распределение дневного уровня по часам. Поставлена основная
версия, связанная командой с платформенным score 0.88220. Альтернативный decay14
не включён. Оригинальный `final.joblib` сохранён в `ml/reference/original_final.joblib`.
Сервис использует его переносимую JSON-версию `ml/artifacts/route_model.json`:
коэффициенты, intercept, поправки, часовые профили и baseline. Исполнение pickle
при старте HTTP-сервиса не требуется.

## Быстрый запуск

Нужен Python 3.12. Из корня репозитория, PowerShell:

```powershell
py -3.12 -m venv ml/.venv
ml/.venv/Scripts/python -m pip install -r ml/requirements.txt
Set-Location ml
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://localhost:8000/docs, затем в `POST /predict` нажать Try it out и ввести:

```json
{"horizon":"day","date":"2025-11-01"}
```

Проверка PowerShell:

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8000/predict/routes -Method Post -ContentType application/json -Body '{"horizon":"day","date":"2025-11-01","routeIds":["17"]}'
```

Нативный backend может использовать `TRAM_ML_MODE=http` и
`TRAM_ML_BASE_URL=http://127.0.0.1:8000`. Для backend в Docker и ML на Windows хосте
нужен `http://host.docker.internal:8000` и привязка uvicorn к `0.0.0.0`.

Полная локальная связка Docker, из корня:

```text
docker compose -f docker-compose.yml -f docker-compose.ml.yml up --build
```

Новый overlay добавляет контейнер `ml`, включает HTTP-режим backend и устанавливает
демо-часы backend на 01.11.2025. Исходные dev/prod Compose и deployment workflow
не изменены. ML доступен на http://localhost:8000/docs, backend на localhost:8080.
Frontend запускается обычным способом из его README.

## Production

`docker-compose.prod.yml` запускает образ `ghcr.io/manticore-mt/tram-forecast/ml`
вместе с Postgres, backend, frontend и Caddy. Backend работает в HTTP-режиме,
обращается к `http://ml:8000` и стартует после healthcheck ML. ML не публикует порт
наружу; его артефакт и справочник остановок встроены в образ. CI тестирует ML и
публикует образ с тегами `latest` и SHA коммита. Workflow Deploy входит в GHCR
на время скачивания образов, ждёт готовности контейнеров и проверяет `/health` ML.
Подробный порядок выпуска и ограничения дат — в `deploy/README.md`.

В ML-контейнер read-only подключается `shared/tram-stops.json`. Для автономного
Python-запуска в `ml/network/tram-stops.json` находится его копия на момент сборки.
После изменения сети обновить копию либо задать `ML_NETWORK_PATH` и перезапустить
ML. Хеш сети включён в `modelVersion` остановочного ответа.

## API

| Endpoint | Результат |
| --- | --- |
| `GET /health` | Проверка загруженного сервиса, версия артефакта |
| `GET /metadata` | Область применимости, источники, даты, описание baseline и ограничений |
| `POST /predict` | Контракт backend: routeId, stopId, points, factors |
| `POST /predict/routes` | Реальные прогнозы уровня маршрута до распределения по остановкам |
| `GET /metrics?origin=2025-09-01` | Исторические WAPE/score, показатели по маршрутам и 61 дню |
| `GET /docs` | Swagger для ручной проверки |

Запросы `predict` принимают `horizon`, `date` и необязательный `routeIds`
(массив строк). Backend без `routeIds` получает все девять маршрутов:
`1,7,11,12,17,25,26,28,50`. Неизвестный маршрут, повторный ID, неправильный горизонт,
дата или лишние поля дают HTTP 422. Маршрут 5 в сервисе не поддержан: в платформенном
CSV он заполнен нулями только для полноты ключей и отсутствует в карте этой сети.

| Горизонт | Выбираемый период | Шаг |
| --- | --- | --- |
| day | Запрошенный день | 24 часа |
| week | Семь дней начиная с date, включая date | День |
| month | Весь календарный месяц, содержащий date | День |
| year | Весь календарный год, содержащий date | Месяц |

Неделя/месяц/год — суммы почасовых маршрутных значений. Округление `np.rint`
выполняется на уровне маршрут × час (ближайшее целое, половины к чётному), как в
оригинальном submission. После агрегации повторного округления нет.
`periodStart` и `generatedAt` имеют ISO 8601 offset +03:00. Московское время —
соглашение интерфейса, а не доказательство timezone исходного `tran_date_time`.

## Даты и качество

История заканчивается 31.10.2025. Дата отсечения модели всегда 01.11.2025.
До 31.12.2025 включительно воспроизводится основная конкурсная версия.
01.01–31.12.2026 — разрешённый по умолчанию сценарий экстраполяции старой истории.
Ответ имеет суффикс `-scenario` в modelVersion и предупреждение в factors. Это
не оперативный прогноз 2026 года, платформа его не оценивала. Свежие факты в модель
не поступают. Для актуального сервиса потребуется новый датасет и переобучение.

`ML_ALLOW_SCENARIO=false` запрещает весь период после декабря 2025. Запросы,
период которых частично выходит за разрешённые границы, отклоняются целиком.
Год 2025 отклоняется: его январь–октябрь предшествуют отсечке. Доступен год 2026
как сценарий. Дата 2027, даже если UI позволяет её выбрать, даёт 422.
Существующий Java-клиент превращает любую такую ошибку ML в недоступность;
при отсутствии сохранённых данных backend вернёт 503. Для аккуратного UI команде
backend следует согласовать диапазон `/api/meta` с `/metadata` ML.

На ноябрь–декабрь сохранено исходное допущение об ограничениях маршрута 50 по
выходным: его значения заменяются исторической почасовой медианой этого режима
с 06.09.2025. На 2026 предполагается нормальная работа, без бесконечного продления
ограничения. Эффект окончания ремонта по будущим фактам не проверен.

## Остановки и участки: демонстрационный режим

Обучение использует только цель `route × date × hour`. Остановочных фактов,
распределения высадок и загрузки вагонов нет. Однако существующий backend требует
stopId и суммирует остановки, чтобы получить маршрут.

Поэтому `/predict` делит каждое маршрутное значение и baseline поровну между
остановками данного маршрута из справочника. Для 297 маршрутных остановок возвращает
согласованный JSON. **Это явное демонстрационное допущение для подключения UI,
а не обученный остановочный прогноз.** Оно помечено в modelVersion
(`uniform-stops-demo`) и в каждой записи factors. Не удалять эту маркировку в UI.
Одинаковые значения остановок намеренны: данные не дают оснований выбрать разные веса.

Остановочные значения дробные, их сумма восстанавливает целый маршрутный прогноз
с точностью double. Независимо округлять каждую остановку нельзя: сумма изменится.
`/predict/routes` возвращает исходные маршрутные значения без stopId. Нельзя
дублировать полный маршрутный прогноз на каждой остановке — backend умножит сумму.
Посадки по остановкам и число пассажиров на перегоне требуют разных дополнительных
данных. Процент заполнения салона, пассажиры на конкретном рейсе и интервалы
неопределённости не выдаются. WAPE-score маршрутов не распространяется на остановки.

## Baseline и коэффициенты

Baseline — историческая медиана за 56 дней перед 01.11.2025 (06.09–31.10), отдельно
для маршрута, эффективного дня недели и часа. Рабочие дни сохраняют номер дня
недели; рабочая суббота относится к пятнице, обычная суббота к субботе, праздники
и воскресенья к воскресенью. При отсутствии группы берётся медиана того же
маршрута/часа за те же 56 дней, затем 0. Это определение зафиксировано для всех
запросов; будущие факты для него не используются.

Пропущенные группы в исходной полной сетке приняты за 0, как в исследовании.
Из baseline ограничения движения не удаляются: это «типичный наблюдаемый уровень
последних восьми недель», а не спрос при полностью работающем маршруте. Для
маршрута 50 выходной baseline поэтому может быть близок к нулю. Деление на нулевой
baseline в UI должно обрабатываться отдельно. Не путать это окно 56 дней с
поправкой Ridge по последним 28 дням и горизонтом прогноза 61 день.

В финальной модели включены календарь, летний период, часовой профиль и недавняя
поправка. Погода и массовые мероприятия выключены. Weather/event/season из
пользовательских настроек уже перемножаются Java backend, ML их второй раз не
применяет. Такие изменения — сценарий пользователя, не измеренный причинный эффект.
Baseline при сценарных поправках остаётся исходным.

## Метрики и факты

`/metrics` считает WAPE из сохранённых независимых по времени прогнозов, округляя
каждую почасовую точку. Доступны origin=2025-07-01 и 2025-09-01:

| Origin | WAPE | Score |
| --- | --- | --- |
| 2025-07-01 | 0.1846142814 | 0.8153857186 |
| 2025-09-01 | 0.1114238204 | 0.8885761796 |

Эти блоки использовались при выборе гиперпараметров, поэтому не являются нетронутым
финальным тестом. Платформенный score 0.88220 передан командой; скрытого факта нет.
Дневные ошибки доступны для построения 30-дневных графиков внутри блока. Суммарный
WAPE надо считать через сумму абсолютных ошибок / сумму фактов, не усреднять
дневные проценты. Непрерывной 90-дневной истории ошибки нет.

Таблица backend `actual_value` рассчитана на факты по остановкам. В этой поставке
она намеренно не заполняется искусственными числами. `/api/model/stats` backend
не подключается к ML `/metrics` автоматически: frontend/backend может использовать
этот endpoint явно или импортировать проверенные маршрутные метрики отдельным путём.
Демонстрационные stop-level actuals не следует выдавать за наблюдения организаторов.

## Файлы и воспроизведение

- `app/engine.py`: календарь, порядок признаков и инференс по JSON.
- `app/main.py`: FastAPI, диапазоны дат, агрегация, baseline, остановочный адаптер и метрики.
- `artifacts/route_model.json`: рабочий артефакт с происхождением и параметрами.
- `network/tram-stops.json`: копия карты; в Compose используется общий справочник.
- `reference/original_final.joblib`: исходный обученный объект для архива.
- `reference/submission.csv`: исходный конкурсный результат, 14 640 строк с маршрутом 5.
- `reference/final_backtest_*.csv`: почасовой факт и прогноз в исторических проверках.
- `reference/final_metrics.csv`, `metrics_by_route.csv`: сохранённые результаты исследования.
- `data/labels_day_*.csv`: исходные агрегаты организаторов для обучения; не 60 млн сырых строк.
- `build_artifact.py`: экспорт доверенного joblib в JSON.
- `train.py`: воспроизведение выбранной модели из labels, без полного поиска моделей.
- `tests/test_service.py`: контракт, эталонные прогнозы, агрегация, даты и воспроизведение обучения.
- `benchmark.py`: воспроизводимый локальный замер HTTP-адаптера.

Из `ml/`, с Python dev-окружением:

```text
python -m pip install -r requirements-dev.txt
python build_artifact.py --source-joblib reference/original_final.joblib --output artifacts/exported_model.json
python train.py --output artifacts/retrained_model.json
python -m pytest -q
python benchmark.py
```

Joblib открывать только из доверенного источника. Рабочий JSON уже поставлен,
переобучение перед первым запуском не нужно. `train.py` фиксирует исходную отсечку
и конфигурацию; он не обещает автоматического обновления модели на новые периоды.

Исходные labels сохраняют 57 551 строку, полная сетка содержит 65 664 строки.
Из обучения дневной регрессии исключаются слишком малые значения и известные
ограничения; оценка backtest сохраняет все часы. Коэффициенты учатся на log1p
дневных сумм с alpha=1, поправка — медиана остатков в логарифмах последних 28 дней.
Профиль часов — 80% сезонного и 20% недавнего (56 дней), нормализован до суммы 1.

## Проверка и производительность

Тесты сравнивают все 13 176 модельных точек ноября–декабря с конкурсным CSV:
полное совпадение после округления. Проверено и повторное обучение из labels.
Сумма остановочных долей сохраняет маршрут; дневные, недельные и месячные суммы
согласованы. Проверяются 2026-сценарий, рабочая суббота, неверные даты и маршруты.

Числа локального замера находятся в `ml/reference/local_benchmark.json` вместе
с описанием окружения и метода. Это последовательный FastAPI TestClient, включает
сериализацию ответа, но не TCP, сеть, Docker и параллельную нагрузку. Нельзя выдавать
их за p95 или сотни RPS продакшен-сервиса. Docker daemon в среде разработки на
момент сборки недоступен; контейнерный прогон требует работающего Docker Desktop.
