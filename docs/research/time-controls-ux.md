# UX-паттерны для управления временем и сценарием (исследование)

Цель: подобрать механику для трёх разных по частоте изменений входов — уровень времени (год→месяц→день), точка фокуса внутри окна (скраббинг) и сценарные коэффициенты (what-if) — на тёмном карто-дашборде. Ниже только источники, которые реально открыты и проверены; там, где страница не отдала нужных деталей (JS-рендер, недоступный раздел доков), это указано явно.

## Референсы

**1. Grafana — Time range picker.** https://grafana.com/docs/grafana/latest/dashboards/use-dashboards/
Три режима: relative-пресеты (last 7d, this month so far и т.п.), absolute (from/to с календарём или текстом), полу-relative (абсолютное начало + `now`). Зум — драг по графику или иконки zoom in/out, диапазон общий на весь дашборд, но у панелей может быть override. Подходит для навигации год→месяц→день как эталон "пресет + произвольный диапазон", но сама механика — форма над графиком, не элемент поверх карты; для дэшборда аналитика подходит лучше, чем для диспетчера с картой на весь экран.

**2. Kepler.gl — Time Playback.** https://docs.kepler.gl/docs/user-guides/h-playback
Плашка внизу карты с гистограммой плотности точек по времени, скользящее окно, которое можно сужать колесом мыши, Ctrl/Cmd+стрелки для панорамирования, play с пресетами скорости 1x/2x/4x. Это ближе всего к нашему кейсу: плавающая полоса времени поверх полноэкранной карты, с масштабируемым окном. Минус — паттерн заточен под point-in-time анимацию треков, а не под дискретные календарные окна (год/месяц/день) с точками агрегации.

**3. Power BI — What-if parameter (числовой слайдер).** https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-what-if
Параметр создаётся как числовой диапазон (min/max/шаг), автоматически получает слайдер и меру; движение слайдера пересчитывает визуал "на лету" (пример: discount 0–50% и график "продажи до/после скидки" рядом). Прямое попадание в механику наших трёх коэффициентов (0.1–3.0, шаг, дефолт 1.0) и в требование жюри "сразу видно, как меняется прогноз" — до/после на одном графике. Не решает вопрос размещения на карте — это стандартная слайсер-панель BI-инструмента, а не floating-виджет.

**4. Яндекс Карты — прогноз пробок по времени.** https://yandex.ru/support/maps/ru/concept/stoppers.html
Три горизонта в одном контроле: «Сейчас» (актуальная ситуация), «Завтра» (ползунок для выбора часа суток — то есть скраббинг), «Выбрать день» (календарь для более дальних дат). Управление в боковой панели, не на самой карте. Это транспортный референс с ровно нашей структурой "горизонт + скраббинг внутри горизонта", но без сценарных параметров.

**5. Google Maps — Typical traffic (по часам).** https://support.google.com/maps/answer/7565193
Документация подтверждает только сам факт: внизу карточки маршрута есть блок "typical traffic by the hour", то есть почасовая типичная загрузка наряду с текущей. Подробности слайдера (перетаскивание, диапазон дат) документация не раскрывает — этот механизм известен из вторичных источников, не из первоисточника; считать частично не проверенным.

**6. NN/g — Date-Input Form Fields: UX Design Guidelines.** https://www.nngroup.com/articles/date-input/
Не про дашборды, а про формы, но два переносимых вывода: (а) календарный picker хорош для дат в пределах года от текущей, для далёких горизонтов лучше текстовый ввод/пресеты; (б) избегать "плавающих" диапазонов (когда выбор одной границы сдвигает шкалу второй) — это прямая рекомендация против конструкций, где смена уровня (год/месяц/день) визуально "прыгает".

**7. Windy.app — переключатель шага прогноза (1ч/3ч).** https://windy.app/blog/tip-forecast-step.html
Первоисточник подтверждает только переключатель гранулярности (1ч/3ч) на детальной странице точки; сама лента-скраббер с анимацией на десктопной Windy.com не поддалась проверке (JS-рендер, WebFetch не получает интерактивный DOM) — считать неподтверждённым и не описывать её механику как факт.

**8. Kibana Discover — гистограмма как time-range контрол.** не проверено (страницы `discover.html` и `document-explorer.html` в текущей версии доков Elastic не описывают клик/драг по бару гистограммы явно; сам паттерн "клик по столбцу = зум по времени" широко известен в комьюнити-обсуждениях, но первоисточник это не подтвердил в открытых разделах). Указываю саму идею как гипотезу, не как проверенный факт.

Uber Movement ("Time Machine", тепловая карта час×день недели) — не проверено: страница на Medium отдаёт 403 при попытке открыть, содержание пересказано только по сниппетам поиска, включать как факт нельзя.

## Сравнение паттернов

| Паттерн | Скорость скраббинга | Ясность перехода год→месяц→день | Заметность дельты сценария | Стоимость реализации | Вписывание в full-screen карту |
|---|---|---|---|---|---|
| 1. Глобальная лента времени (Windy/Kepler-стиль) | высокая (drag/scroll) | средняя — лента должна менять масштаб при смене уровня, требует доп. логики | низкая — лента не про сценарий | средняя-высокая (кастомный canvas/SVG компонент) | хорошее — floating-бар снизу, привычно для карты |
| 2. Date picker + пресеты (Grafana/GA) | низкая — открыть попап, выбрать | высокая — уровни как явные пресеты/вкладки | не применимо | низкая (готовые компоненты) | среднее — требует попапа поверх карты |
| 3. Гистограмма как контрол (клик/brush) | средняя | высокая — сам бар = единица уровня, клик = drill-down | низкая | средняя — нужен chart с обработкой клика/brush | хорошее — совпадает с идеей "клик = drill" уже принятой для объекта |
| 4. Плавающие виджеты (Kepler filter panel) | зависит от виджета внутри | средняя | средняя, если рядом второй виджет с дельтой | средняя | отличное — уже наш паттерн (глянцевые панели) |
| 5. Отдельная what-if панель (Power BI) | не применимо (это про сценарий) | не применимо | высокая — специально для этого спроектирован (до/после) | низкая-средняя (3 слайдера + пересчёт) | хорошее как отдельная плашка, не конкурирует с временем |

## Выводы

- Ни один единый паттерн не закрывает все три входа сразу: горизонт, фокус-скраббинг и сценарий явно тянут к разным виджетам (пресет/таб для горизонта, лента или гистограмма для фокуса, слайдеры для сценария) — это подтверждают и Яндекс.Карты (горизонт и скраббинг — два разных контрола в одном блоке), и Power BI (сценарий всегда отдельный слайсер).
- Паттерн "гистограмма как контрол" (Kibana-идея, не проверено) концептуально ближе всего к уже принятому drill-down по клику на карте — тот же жест "клик по элементу = переход глубже", но сам механизм не подтверждён в открытых доках Elastic, использовать с осторожностью и не как проверенный референс.
- NN/g прямо предостерегает от "плавающих" диапазонов при смене уровня — при переключении год→месяц→день лучше делать эффект "той же ленты, что просто меняет масштаб", а не полностью пересобирать виджет.
- Для сценарных коэффициентов Power BI what-if — самый прямой и дешёвый в реализации референс: числовой слайдер с шагом и дефолтом, эффект виден сразу на том же графике (не в отдельном модальном окне) — совпадает с критерием жюри.
- Windy/Kepler-стиль ленты снизу карты — самый тяжёлый в реализации (кастомный компонент с масштабируемой шкалой), но единственный из проверенных, который явно живёт "поверх карты" как единый физический объект, а не как попап.
