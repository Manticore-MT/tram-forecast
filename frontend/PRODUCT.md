## Platform

web

## Users

Диспетчер трамвайной сети (основной экран «Диспетчер», US1-6) и руководитель/стейкхолдер (экран
«Обзор сети», US7-10). Оба работают в реальном времени с прогнозом пассажиропотока трамваев Москвы:
диспетчер — по конкретному маршруту и времени, чтобы решить, где перераспределить подвижной состав;
руководитель — по сети целиком, чтобы оценить доверие к модели и общую нагрузку.

## Product Purpose

«Поток» — сервис прогноза пассажиропотока трамвайных маршрутов Москвы (трек 02 «Хакатона
Московского транспорта», 25.09–03.10.2026, команда Manticore). Показывает прогноз загрузки на
горизонтах день/неделя/месяц/год, на реальной карте (OSM) и во временной шкале, с возможностью
применить сценарные поправки (погода/событие/сезон) и увидеть, как меняется прогноз.

## Positioning

Единственный сдаваемый продукт хакатона от команды — не воссоздание существующего интерфейса
(готового дизайна диспетчерской системы не было предоставлено), а самостоятельно спроектированный
бренд и UI поверх брифа оргов и реального API бэка/ML-контура команды.

## Operating Context

- Данные — реальные (не синтетика): бэк отдаёт `forecast`/`baseline` (и `actual` там, где есть) по
  маршруту; сеть целиком — сумма по маршрутам без `actual` (открытый вопрос Кириллу,
  `docs/open-questions.md`).
- Уровень «остановка» **убран** из продукта (решение бэка 26.09/27.09 — данных по остановкам и
  участкам между ними нет и не будет). Остановки на карте — только геометрия и тултип с названием,
  не интерактивный уровень прогноза.
- Сценарные поправки (погода/событие/сезон) пересчитывают прогноз через API, не локально.
- Экспорт — для диспетчера (не файл сабмита хакатона); формат сейчас CSV, XLSX ожидает бэк.
- Хакатон, жёсткий дедлайн 27.09.2026 23:59 МСК на git-гигиену (после — обычные правила), сама сдача
  — 03.10.2026.

## Capabilities and Constraints

- Стек: Vite + React 18 + TypeScript, Tailwind v4, Leaflet/OSM для карты, zustand для UI-состояния,
  React Query для серверных данных.
- Русскоязычный UI без исключений (см. `README.md` § «ОСНОВЫ КОНТЕНТА» — вы-форма, sentence case,
  «ёлочки», без эмодзи, без англицизмов кроме признанных технических терминов).
- Один акцентный цвет — сигнальный красный `#F0392B`, скупо (не больше одного акцентного элемента на
  экран). Пятиступенчатая шкала загрузки `--load-1…5` — единственная разрешённая цветовая шкала
  загрузки, не путать с акцентом.
- Тёмная тема по умолчанию и практически единственная; `[data-theme="light"]` существует только для
  печати/экспорта, не как пользовательский переключатель.
- Известные незакрытые пробелы данных (не решать самостоятельно, см. `docs/open-questions.md`):
  факт для сети/«Обзора», доверительный интервал прогноза, MAPE/RMSE/R² в статистике модели, внешние
  факторы на уровне сети, ВСМ.

## Brand Commitments

- Название продукта — **«Поток»**, команда — **Manticore**, трек 02.
- Логотип и знак-булавка — готовые SVG-ассеты (`src/assets`), угловатая «М» задаёт трекинг display-

- Карта — только реальная геометрия (OSM-подложка под тёмным фильтром), никогда не рисованный город.

## Product Principles

1. Честность важнее полноты: если данных нет (доверительный интервал, факт по сети, остановки), это
   явно обозначается или убирается, а не имитируется синтетикой.
2. Один экран — один способ прочитать нагрузку: цветовая шкала `--load-*` для загрузки, акцентный
   красный — только для «сейчас/live» и пиков, никогда оба значения одновременно на одном элементе.
3. Диспетчер работает с картой и временем как единым состоянием (zustand `store.ts`): выбранный
   объект, время и сценарий синхронны между всеми панелями и обоими экранами.
4. Русский язык и вы-форма — без исключений, даже в служебных состояниях (ошибки, пустые состояния).
5. MVP хакатона: до дедлайна разрешено переписывать начисто и форсить историю; после — обычные
   правила git-гигиены.

## Accessibility & Inclusion

Отдельного требования от оргов/пользователей не зафиксировано. Клавиатурная навигация уже частично
реализована (полоса «Время» — `role="slider"`, стрелки/Shift для интервала, Tab-фокус); формального
стандарта (WCAG AA и т.п.) как обязательного требования не установлено.
