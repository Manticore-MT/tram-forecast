# Design System: Поток

## Overview

**Creative North Star: "The Night-Shift Control Room"**

«Поток» — ночная дежурная диспетчерская, не маркетинговый лендинг: тёмная поверхность по умолчанию
(белый-на-чёрном логотип — единственная твёрдая улика бренда), один сигнальный акцент, который
включается только там, где кто-то должен отреагировать (live-статус, пик загрузки, изменённый
сценарий), и вся остальная плотность данных — в спокойной нейтральной шкале. Плотность продукт-UI
никогда не превышает 32px внутреннего паддинга — это приборная панель, а не выставочный стенд.

Карточки — заливка + волосяная линия, никогда drop shadow; на тёмном фоне «поднятость» читается
светлее, а не тенью. Карта всегда настоящая (OSM под тёмным фильтром), геометрия остановок и
маршрутов никогда не рисуется вручную. Числа — всегда табличным моно (JetBrains Mono), текст —
геометрическим гротеском (Manrope) с тугим трекингом на дисплее. Движение короткое и почти линейное —
«вокзальное табло», не пружина.

**Key Characteristics:**
- Тёмная приборная панель: `--bg-page` = `#0E1113`, поверхности повышаются светлее, не тенью.
- Один акцент на экран: сигнальный красный `#F0392B` — только CTA, «сейчас», пик, изменённый сценарий.
- Пятиступенчатая шкала загрузки — единственная разрешённая цветовая кодировка величины (зелёный →
  салатовый → янтарный → оранжевый → красный).
- Плоские карточки со стеклянным вариантом только поверх карты/графика.
- Табличные (моно) цифры везде, где число сравнивается по вертикали.

## Colors

Один главный акцент на почти монохромной тёмной основе; данные и статусы держат свои отдельные шкалы,
чтобы не путать «это акцент» с «это уровень загрузки».

### Primary
- **Сигнальный красный** (`#F0392B`, hover `#FF6152`, press `#C82417`): единственный hero-акцент —
  основные CTA, маркер «сейчас/live», достигнутые вехи, пиковая загрузка. Не больше одного заметного
  красного элемента на экран — это редкость, не украшение.

### Neutral (тёмная шкала — по умолчанию)
- **Ink 900** (`#0E1113`) — `--bg-page`, базовый фон.
- **Ink 800** (`#15191C`) — `--bg-surface`, дефолтная поверхность карточки.
- **Ink 700 / 600** (`#1C2226` / `#252D33`) — вторая/повышенная поверхность (`--bg-surface-2`,
  `--bg-elevated`).
- **Белый** (`#FFFFFF`) — основной текст (`--text-primary`).
- **Slate 200/300** (`#9AA6AE` / `#697680`) — вторичный/приглушённый текст.
- **Волосяные линии** — `rgba(255,255,255,.09/.16/.28)` (subtle/default/strong), никогда сплошной
  серый бордер.

### Named Rules
**The One Accent Rule.** Сигнальный красный встречается на экране один раз заметно (или не встречается
вовсе) — если нужно выделить второй элемент, для этого есть шкала загрузки или статусные токены
(`--status-ok/warn/danger/info`), не второй красный.

**The One Data Hue Rule.** Факт/сравнение на графиках — один выделенный дата-цвет, сигнальный циан
(`--data-actual`, `#22D3EE`). Это не «цветовая палитра» для красивости, а один конкретный цвет с одной
работой: контрастировать линию факта с красным прогнозом. Больше никаких дата-цветов в системе нет.

## Typography

**Display Font:** Manrope (с Helvetica Neue, Arial как фолбэком)
**Body/UI Font:** Manrope
**Metric/Mono Font:** JetBrains Mono — только для чисел, всегда табличные (`tabular-nums`)

**Character:** Геометрический гротеск, тугой на дисплее (трекинг −0.03em, начертание 800, интерлиньяж
< 1) — угловатость читается от «М» в логотипе; на теле текста тот же шрифт расслабляется до 400 и
обычного интерлиньяжа. Моно-цифры — сознательный «технический» контраст к гуманистическому Manrope.

### Hierarchy
- **Display m** (800, clamp(28–44px), 1.06): изредка — заголовки крупных секций «Обзора».
- **H1** (700, 32px, 1.14) / **H2** (700, 24px, 1.2) / **H3** (600, 20px, 1.3) / **H4** (600, 16px,
  1.35): структура экрана и панелей («Детали», «Маршрут № …»).
- **Body** (400, 16px, 1.55) / **Body-s** (400, 14px, 1.5): пояснительный текст, редко на приборной
  панели.
- **UI / UI-s** (600, 14px/13px, 1): подписи кнопок, вкладок, значений в панелях — самый частый
  текстовый стиль в продукте.
- **Caption** (500, 12px, 1.4): вторичные подписи, легенды, метки времени.
- **Eyebrow** (700, 12px, 1.2, tracking 0.14em, UPPERCASE): единственное место, где разрешены
  заглавные буквы — маленькие ярлычки-заголовки панелей («Детали», «Сценарий»).
- **Metric / Metric-xl** (700, 28px/48px, JetBrains Mono): числа, которые сравниваются вертикально
  (прогноз, отклонение, KPI-карточки).

### Named Rules
**The Tabular Numerals Rule.** Любое число, которое стоит рядом с другим числом того же смысла
(отклонение, прогноз, KPI-ряд), набирается табличным моно — иначе цифры «прыгают» по ширине и колонка
не читается как колонка.

**The Eyebrow-Only-Caps Rule.** ВСЕ ЗАГЛАВНЫЕ существуют только в `.mt-eyebrow`; заголовки и кнопки —
всегда sentence case.

## Layout

Сетка 4px. Продуктовый UI (диспетчерская, обзор) не превышает 32px внутреннего паддинга ни у одной
панели — это приборная доска, плотность важнее воздуха. Плавающие панели над картой (`shared/Floating`)
— единственное место, где живёт абсолютное позиционирование; сама панель не знает своей позиции, только
размер. Маркетинговые/документные секции (вне продукта) дышат на 96px (`--space-section`, hero — 160px)
и ограничены шириной контента 1240px — но это не сценарий диспетчерской.

## Elevation & Depth

Гибрид без теней по умолчанию: на тёмном фоне «поднятость» — это более светлая заливка + волосяная
линия (`--inset-hairline`), не `box-shadow`. Настоящая тень появляется только для истинных оверлеев —
меню, диалоги, тултипы на карте (`--src-shadow-sm/md/lg`, `--src-shadow-accent` — красное свечение
только под акцентными элементами). `glass`-карточка (6% белой заливки + blur 16px) легальна только
поверх карты или графика/цветного фона — это не дефолтный стиль карточки, а специально проявленное
исключение для контекста «поверх насыщенного фона».

### Named Rules
**The Flat-By-Default Rule.** Обычные поверхности плоские (заливка + hairline); тень — исключение для
overlay-слоя, не украшение карточек в потоке.

## Shapes

Радиусы щедрые и растут по шкале 6 / 10 / 14 / 20 / 28px плюс pill — мелкие элементы (иконки,
чипы) на 6-10px, панели и карточки на 14-20px, крупные элементы на 28px. Бордеры — только
волосяные (1-2px, `rgba(255,255,255,…)`), никогда сплошной непрозрачный серый.

## Components

### Buttons
- **Shape:** `--radius-md` (14px). Было `rounded-lg` (20px) в `ui/button.tsx` — на 36px-высоте это
  визуально даёт полную капсулу (радиус ≥ половины высоты), из-за чего кнопка рядом с полем той же
  высоты (например «Сегодня» рядом с датой в шапке диспетчера) выглядела другой формой без всякого
  умысла. Поправлено на `radius-md`, как и задокументировано.
- **Primary:** сигнальный красный фон, белый текст, паддинг по шкале `--space-*`.
- **Ghost/Secondary:** прозрачный/нейтральный фон, текст `--text-secondary`, hover — `--glass-fill`.
- **Hover/Focus:** переход `--transition-ui` (140ms, `cubic-bezier(.2,.6,.2,1)`); фокус — контур
  `--focus-ring` (циан, не красный — фокус и акцент-цвет всегда разные каналы).
- **Именованные исключения из radius-md** (не баг, если увидишь их такими):
  - `Tabs` (`variant="pill"`) — сегментный переключатель, всегда `rounded-pill`. Это не кнопка, это
    отдельный компонент навигации.
  - `IconButton` — всегда `rounded-full` (задано явно в компоненте, не наследуется от Buttons-радиуса)
    — «квадратная по footprint, круглая по форме» кнопка на одну иконку.

### Badges/Tags
- **Style:** заливка на 10-15% непрозрачности своего тона + кольцо (`ring-1`) того же тона на 30-35%;
  текст — насыщенный вариант того же тона. Тон = семантика (`neutral/accent/ok/warn/danger/info`), не
  декоративный выбор.

### Cards / Panels
- **Corner Style:** `--radius-md` (14px) по умолчанию.
- **Background:** `surface` (дефолт, `--bg-surface`) → `raised` (`--bg-elevated`) → `glass` (только
  поверх карты/графика) → `accent` (сплошной красный, редко) → `outline` (только волосяная линия).
- **Shadow Strategy:** нет, кроме overlay-контекста (см. Elevation).
- **Internal Padding:** плавающие панели диспетчерской унифицированы на `--space-4` (16px); панель
  «Детали» была исключением на `--space-6` — приведена к общему `--space-4`.

### Inputs / Sliders
- **Style:** заливка `--bg-surface-2` (или контекстная `--control-surface`, см. ниже), волосяная
  линия внутрь (`--inset-hairline`), без бордера снаружи.
- **Focus:** внутренняя рамка `shadow: inset 0 0 0 2px var(--focus-ring)`, не внешний outline — чтобы
  не двигать layout.
- **Range slider (native):** трек 4px `--border-default`, ползунок 16px круг `--brand-accent` с
  2px-окантовкой в цвет фона — единственное место, где нативный `<input type=range>` не обёрнут кастомным
  компонентом.
- **Контролы внутри `glass`-панелей.** `--bg-surface-2` — непрозрачный тёмный ink, рассчитанный на то,
  что он на ступень светлее сплошной карточки под ним (`surface`/`raised`). У `glass`-панели нет
  сплошного цвета, чтобы быть на ступень темнее — она сама почти прозрачная (6% белого поверх карты).
  Поэтому инпут внутри неё раньше читался не как «следующая ступень поверхности», а как чёрная дыра,
  вырезанная в стекле (найдено живьём: дата/число в «Сценарии» на диспетчерском экране).
  Решение — CSS-переменная `--control-surface`, а не проп: `Card` (`tone="glass"`) переопределяет её на
  `--glass-well` (`rgba(255,255,255,.12)`, светлее и полупрозрачнее, чем `--glass-fill`, чтобы
  оставаться материалом того же стекла, а не отдельной пластиковой вставкой); `Input` и `Tabs`
  (`variant="pill"`) читают `bg-(--control-surface,var(--bg-surface-2))` — так им не нужно знать, в
  какой карточке они лежат, а обычные (не-glass) места остаются на `--bg-surface-2` как раньше.

### Tooltip
- Заливка `--bg-elevated`, текст `--text-primary`, без тени (короткая подсказка, не overlay-меню);
  стрелка обязана совпадать по заливке с телом подсказки — это разбиралось отдельно как баг (была
  белая по shadcn-дефолту вместо `--bg-elevated`).

### Time strip (сигнатурный компонент)
Гистограмма-слайдер, не декоративный график: столбики = `role="slider"`, высота = загрузка, штриховка
= «это ещё прогноз, не факт» (легенда обязана визуально совпадать с реальным паттерном штриховки),
пунктирный контур = «прогноз без поправок сценария». Фокус — только по Tab, не по нативной эвристике
`:focus-visible` (которая иначе включается на любую клавишу, включая Shift во время выбора интервала).

## Do's and Don'ts

### Do:
- **Do** использовать сигнальный красный редко и заметно — если он есть на трёх элементах экрана,
  это уже не акцент.
- **Do** держать числа в JetBrains Mono/tabular-nums везде, где они выстроены в столбец.
- **Do** гасить нативный `:focus-visible` явно (`focus-visible:outline-none`) там, где свой
  keyboard-vs-pointer детектор точнее нативной эвристики (полоса «Время»).
- **Do** заливать «поднятость» светлее, не тенью, вне overlay-слоя.

### Don't:
- **Don't** использовать фиолетовый/мультихью-градиенты — факт держится на одном дата-цвете циан,
  загрузка — только пятиступенчатая `--load-*`.
- **Don't** объявлять токен «для будущего использования» или «как фирменный элемент системы» без того,
  чтобы он действительно был применён в отправленном UI — неиспользуемый токен — это не часть дизайн-системы,
  а просто пожелание.
- **Don't** ставить `glass`-карточку там, где под ней не карта и не график/цветной фон — это не
  дефолтный стиль карточки.
- **Don't** превышать 32px внутреннего паддинга в продуктовом UI — это приборная панель, не
  маркетинговая секция.
- **Don't** давать одному Badge/бейджу произвольные `text-xs`/пиксельные значения в обход
  `--type-*`-шкалы — тон меняется через `TONE_COLOR`/`toneClasses`, размер/вес — всегда через токен
  типографики (`text-ui-s`/`text-caption`), не Tailwind-примитив напрямую.
