# Данные, область применимости, коэффициенты

Эта карточка описывает проверяемые возможности поставки. Реестр ссылок и сохранённых входных данных: [FACTORS.md](FACTORS.md). Числа ниже относятся к отдельному экспериментальному профилю CatBoost, если прямо не указан конкурсный CSV.

## Четыре категории: использование и подтверждение эффекта

| Категория | Признаки | Источник | Проверка |
|---|---|---|---|
| Календарь/сезонность | Эффективный день недели, рабочий/праздничный/сокращённый день, лето, годовые синус/косинус | [Постановление №1335](https://government.ru/docs/all/155500/), [официальная новость](https://government.ru/news/52895/) | `all` против `without_calendar` |
| Погода | Температура и ощущаемая температура, осадки/снег/ветер, осадки за 3 часа | [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api), точный запрос в отчёте | `all` против `without_weather` |
| Дорожный трафик | Последняя опубликованная скорость/баллы не старше 3 часов, давность, признаки отсутствия сводки | [Официальный канал ЦОДД/Дептранса](https://t.me/s/DtOperativno); 101 запись с отдельными `sourceUrl` в `data/traffic_reports_2025_deptrans.json` | `all` против `without_traffic`, отдельно часы с наблюдениями |
| Прочие: изменения движения | Ограниченный режим маршрутов 7/50 в выходные 06.09–14.11.2025 | [Ограничения](https://t.me/DtOperativno/22627), [восстановление](https://t.me/DtOperativno/23565) | `all` против `without_events`, отдельно затронутые часы |

Данные перечислены в реестре `ml/FACTORS.md`; фактическое использование нового
профиля определяется группами признаков `featureGroups` и сохранёнными моделями.
Изменения движения структурированы вручную из сообщений, отдельная языковая
модель не обучалась. Два сообщения относятся к одной категории.

Эксперимент использует отдельную модель CatBoost. В основной конкурсный CSV
0.89212 она не подставлена: этот score относится только к ранее отправленному файлу.
Она реально доступна через ML API и в блоке внешних факторов веб-приложения.
Наличие измеренного отрицательного эффекта погоды не доказывает улучшение качества от всех четырёх категорий. Конкурсный score 0.89212 нельзя приписывать этому профилю.

### Протокол и интерпретация

Измеренный результат выбранного профиля (26 568 route-hour точек, июль–октябрь):

| Состав | WAPE | Эффект включения исключённой категории |
|---|---:|---:|
| Все четыре категории | 14.872481% | — |
| Без календаря | 26.051827% | +11.179346 п.п. |
| Без погоды | 14.591611% | −0.280870 п.п. |
| Без трафика | 15.112902% | +0.240420 п.п. |
| Без изменений движения | 15.178610% | +0.306128 п.п. |

Погода ухудшила общий WAPE во всех трёх окнах. На дождливых часах июля–августа
WAPE снизился с 21.199005% до 20.611904%, но в сентябре и октябре дождливые часы
ухудшились. Нельзя обобщать локальный выигрыш на весь период или выдавать его за
основной результат. Для трёх других категорий суммарное улучшение подтверждено.

- Проверки: 01.07–31.08, 01.09–30.09 и 01.10–31.10.2025. Периоды не пересекаются.
- Для каждой проверки используются только целевые значения строго до её начала.
- Пять вариантов обучены заново на одинаковых строках, с одинаковым seed и
  гиперпараметрами. Различается только наличие одной группы внешних признаков.
- Масштаб целевой величины зависит только от маршрута и обучающей истории;
  календарь/погода/ограничения не спрятаны в базовом прогнозе или знаменателе.
- Итоговый WAPE = сумма абсолютных ошибок всех окон / сумма фактов всех окон.
  Среднее процентов по окнам не используется. Почасовые прогнозы округлены.
- Эффект = WAPE без категории − WAPE всех категорий. Положительный эффект
  означает улучшение в этой конкретной модели, отрицательный — ухудшение.
- Проверены два представления погоды: исходные величины и температурная аномалия
  относительно нормы 2015–2024 с более грубыми признаками осадков/ветра.
  Исходное представление оставлено по меньшему суммарному WAPE. Альтернатива
  сохранена в `reference/factor_anomaly_trial.json`. Это подбор на исторических
  проверках, поэтому мы не называем их независимым финальным тестом.
- Дождливые часы (осадки ≥0.5 мм/ч) исследованы дополнительно после получения
  общего результата. Это явно помеченный exploratory-анализ, не новая основная метрика.
- В июле и на начало сентября нет примеров осеннего ограничения в обучении:
  модель не может выучить его эффект заранее, поэтому абляция может давать ноль.
- Коррелированные источники и взаимодействия делают эффекты неаддитивными.
  Это предсказательный вклад, а не доказательство причинного влияния на пассажира.

## Область определения и адаптации

| Параметр | Поддерживается | Ограничение |
|---|---|---|
| Маршруты | 1, 7, 11, 12, 17, 25, 26, 28, 50 | Маршрут 5 в этот профиль не входит; неизвестные маршруты отклоняются |
| Цель | Число успешных валидаций по маршруту × час, время Москвы | Не число людей в салоне, не высадки, не уникальные пассажиры |
| Ночь | 00:00–04:59 = 0; час 05:00 обучен по записям 05:30–05:59 | Технологические записи до 05:30 исключены |
| История | Январь–октябрь 2025 | Пропущенные route-hour группы принимаются за 0; возможны сбои сбора |
| Новый профиль факторов | 01.11–31.12.2025, 24 точки на выбранный день | Предрасчёт сохранённых моделей; качество на этих датах не измерено |
| Основной API | День/неделя/месяц; 2026 — сценарий, год только 2026 | Score конкурсного CSV относится только к отправленному файлу за ноябрь–декабрь 2025, не к годовому сценарию и не к четырёхфакторному профилю |
| Остановки/участки | Реальная остановочная модель отсутствует | Равномерный демонстрационный адаптер основного API не является измеренной загрузкой |
| Baseline | Медиана 56 дней до 01.11 по маршруту × типу дня × часу | Заморожен, включает ограничения движения; для 50 возможны несопоставимые режимы |
| Погода | Ретроспективный реанализ Москвы | Это не прогноз, доступный в момент начала горизонта |
| Трафик | Нерегулярные общегородские сводки с TTL 3 часа | Низкое покрытие, не скорости конкретного трамвая/перегона |
| События | Подтверждённые сообщения о 7/50 | Рабочая суббота 01.11 требует отдельной проверки; будущие новые события не обнаруживаются автоматически |


Перенос на новый маршрут:

1. Согласовать идентификатор и целевую величину, собрать успешные валидации с
   временными метками и признаком результата. Фильтровать технологические часы,
   документировать пропуски. Желательна история разных будних/выходных режимов;
   для годовой сезонности нужен полный год, лучше несколько лет.
2. Подготовить route-hour сетку, проверить дубликаты и сохранение сумм; добавить
   маршрут в справочник и список поддерживаемых маршрутов, обновить внешние события.
3. Получить погоду для нужной территории и пригодный источник трафика. Проверить
   временную зону, доступность на момент прогноза и покрытие; не переносить эффект
   московских общегородских сообщений на другой город автоматически.
4. Переобучить все версии, пересчитать baseline, провести отложенные временные
   проверки на новом маршруте. Сравнить с простым профилем «день недели × час».
5. Опубликовать новую версию артефактов, область дат и метрики. Обновить снимки
   backend управляемым refresh, сохранив предыдущую версию для отката.

Перенос на новый период: обновить историю/календарь/режимы движения и внешние
источники; сравнить распределения объёмов и ошибок, переобучить и повторить
временную проверку. Сохранение API-контракта не подтверждает качество на новом периоде.

## Коэффициенты и агрегация

Ручной сценарий backend: `forecast × weather × event × season`.
Все коэффициенты 0.1–3.0, нейтральное значение 1. Поправка применяется при чтении,
не накапливается, не меняет факты и baseline. UI показывает исходное/изменённое
значение и итоговый множитель. Это не отключение признаков модели.

Агрегация и очистка выполняются
офлайн, почасовые метки версионированы. `filter_night_labels.py` воспроизводит
границу 05:30, `train.py` воспроизводит основной Ridge, `factor_evidence.py` —
экспериментальные модели. День/неделя/месяц агрегируются суммированием единой
почасовой цели. Тесты проверяют сохранение сумм и неизменность baseline при коррекции.

## Воспроизведение

Из каталога `ml`:

```sh
python -m pip install -r requirements-factors.txt
python factor_evidence.py --weather-mode raw --publish-web
python verify_factor_models.py
python -m pytest -q tests/test_factor_evidence.py tests/test_service.py
```

`artifacts/factors/evidence.json` содержит метрики, версии библиотек, SHA-256 входов
и моделей. `backtest_*.csv` содержит истинные и все пять прогнозных значений;
`models/*.cbm` + `models/*.json` — обученные модели, порядок признаков и масштабы.
`forecasts.json` — их инференс на ноябрь–декабрь.

HTTP ML: `GET /factors/evidence` и
`GET /factors/predict?date=2025-11-15&routeId=17&without=weather`.
Это отдельный экспериментальный профиль с `platformScore=null`.
Frontend использует побайтово одинаковые отчёт и предрасчёт из `public/factors`;
CI проверяет их совпадение с ML-артефактами.
